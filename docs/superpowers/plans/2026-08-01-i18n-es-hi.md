# i18n (es, hi) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** All five platform pages served in English, Spanish, and Hindi (15 pages) with a correct hreflang cluster, fully translated UI including the React apps, ads and maintenance behavior intact everywhere.

**Architecture:** Locale shells under `frontend/es/` and `frontend/hi/` (translated copies with static hero snapshots), shared React apps taking a typed `strings` prop from 10 new locale entry files, backend route loop over 15 pages x clean/.html forms. Spec (rev2, binding): `docs/superpowers/specs/2026-08-01-i18n-design.md`. ALL copy comes VERBATIM from `docs/superpowers/specs/2026-08-01-i18n-translations.md` (rev2): never retranslate, never improvise a string.

**Tech Stack:** Vite 6 MPA (16 entries), React 19, FastAPI.

## Global Constraints

- NO em dashes, NO emoji anywhere. Conventional commits ending with: `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`
- Backend from `backend/` with venv active; frontend from `frontend/`. TDD. Warnings baseline 7. Branch `feature/i18n-es-hi` (exists).
- Copy fidelity: every user-visible string on es/hi surfaces matches the translations doc character-for-character. English behavior and rendering must be UNCHANGED end to end (the en pages are live and earning).
- `<!--ADS-->` marker: exactly once per shell (15 shells), never inside `#root` snapshots.
- NO component reads strings at module scope (spec Blocker rule). Strings reach apps via props with English defaults.
